# Project: AI Audio Cleaner — Auphonic-Inspired Web Application

## 1. Project Objective

Create a functional, beginner-friendly Python web application for cleaning spoken-word audio, inspired by Auphonic. The application should improve the clarity and consistency of recorded speech by reducing unwanted background noise and normalizing loudness.

Use **FastAPI** for the backend, Python for audio processing, and a clean, responsive frontend using HTML, CSS, and JavaScript or an equally suitable lightweight framework.

I am a beginner with no coding background. Make sensible technical decisions, implement the application step by step, and explain important setup and deployment requirements in simple language.

## 2. Core Audio-Processing Features

### A. Audio Upload
- Accept WAV and MP3 audio files.
- Provide a drag-and-drop upload area and a standard file-selection button.
- Display the selected filename, file size, and audio duration when available.
- Validate file types and reject unsupported or corrupted files with clear error messages.
- Set a configurable upload-size limit and explain how to increase it safely.
- Never overwrite the user's original recording.

### B. AI Noise Reduction
Integrate **DeepFilterNet** or a compatible, maintained DeepFilterNet speech-enhancement implementation.

The processing pipeline should:
- Reduce steady background noise such as fans, air conditioners, computer noise, and room hiss.
- Reduce electrical hum and microphone hiss where the model or supplementary processing can handle them.
- Preserve speech intelligibility, natural vocal tone, and consonant clarity.
- Avoid excessive processing that makes voices sound metallic, muffled, or robotic.
- Allow the application to report a clear error if the noise-reduction model is unavailable or fails.

Do not claim that all noises can be removed. Strong loudspeaker feedback, severe clipping, and overlapping sounds may not be fully recoverable.

### C. Consistent Speech Loudness
Use **pyloudnorm** for integrated loudness measurement and normalization, targeting **-16 LUFS** for the processed audio.

Requirements:
- Measure loudness before and after processing when supported.
- Normalize to the target only when the audio signal allows it.
- Use peak limiting or another suitable true-peak control stage to reduce the risk of clipping.
- Include sensible safeguards for silence, very quiet recordings, and files that cannot reach the target safely.
- Preserve natural volume changes and vocal dynamics where possible.
- Report the measured output loudness and peak level when available.

Use appropriate processing order: decode audio, reduce noise, measure and normalize loudness, control peaks, and export the result. Adjust the pipeline when technical testing shows a better order is necessary.

### D. Audio Format and Export
- Preserve the original recording by default.
- Export cleaned audio as WAV or MP3.
- Let the user choose the output format when practical.
- Preserve the original sample rate where appropriate, or resample correctly if required by the model.
- Avoid unnecessary quality loss during format conversion.
- Use FFmpeg or a suitable Python library for reliable decoding, resampling, encoding, and metadata handling.

## 3. User Interface

Build a modern, minimal, responsive interface inspired by professional audio-cleaning tools.

Include:
- A clear application name and short description.
- A drag-and-drop upload panel.
- A processing settings section showing the -16 LUFS target.
- A prominent 'Clean Audio' button.
- A processing indicator with meaningful status messages.
- An error display with actionable explanations.
- An original-audio player and a cleaned-audio player.
- A before-and-after comparison option.
- A download button that becomes available only after successful processing.
- A reset option for starting another recording.

Make the interface usable on desktop and mobile screens. Do not imitate Auphonic's branding, logo, or proprietary interface assets.

## 4. Processing Progress and Long Files

The application should support reasonably long recordings, not just short demonstration clips.

- Avoid processing long recordings synchronously inside a normal webpage request.
- Use background jobs or a task queue when appropriate.
- Show real processing status and progress wherever measurable.
- Do not invent percentage progress if the backend cannot measure it reliably.
- Keep the browser responsive while processing.
- Handle interrupted jobs, timeouts, temporary failures, and unavailable workers gracefully.
- Clean up temporary files after processing and provide configurable file-retention limits.
- Explain the maximum supported duration and file size for the initial deployment.

Design the architecture so more powerful processing servers can be added later without rebuilding the frontend.

## 5. Backend and Security

- Keep audio-processing logic separate from the web interface.
- Validate uploaded files and generate safe internal filenames.
- Prevent users from accessing other users' files or processing jobs.
- Do not expose server credentials, API keys, filesystem paths, or internal errors in the frontend.
- Use environment variables for configuration and secrets.
- Add basic request limits and upload-size controls.
- Do not log audio contents or sensitive personal information.
- Make temporary-file deletion and failure cleanup reliable.
- Return clear, structured errors to the frontend.

Authentication is not required for the first prototype, but structure the app so accounts and usage limits can be added later.

## 6. Technical Implementation

Use:
- Python and FastAPI.
- DeepFilterNet for speech enhancement.
- pyloudnorm for loudness measurement and normalization.
- FFmpeg for audio decoding, conversion, and encoding.
- A lightweight HTML/CSS/JavaScript frontend unless another framework provides a clear benefit.

Before implementation, verify that the selected DeepFilterNet package and model can run in the target deployment environment. Check Python-version compatibility, system dependencies, CPU/GPU requirements, model licensing, and expected processing time.

Do not substitute a fake processing function or a browser-only noise filter for the actual audio-processing engine.

If DeepFilterNet cannot run directly on the web host, separate it into a dedicated audio-processing service and connect it through a secure backend API. Keep the first version as simple as possible.

## 7. Deployment

Deploy the application to a publicly accessible HTTPS URL.

- Use a hosting environment that supports the required Python packages and FFmpeg dependencies.
- Provide a requirements.txt or equivalent dependency file.
- Include clear startup commands and deployment configuration.
- Configure environment variables securely.
- Add a health-check endpoint.
- Explain the limitations of the selected hosting plan, including sleep behaviour, memory, processing time, upload limits, storage, and usage costs.
- Do not assume that the hosting provider can run DeepFilterNet or that its free plan supports long audio-processing jobs.
- Ensure the deployed application can actually process a test file before declaring deployment complete.

## 8. Testing and Quality Assurance

Test with several short recordings before attempting long files:
- Clean speech with little background noise.
- Speech recorded with fan or air-conditioning noise.
- Speech with microphone hiss or electrical hum.
- Speech with fluctuating volume.
- Quiet speech and recordings with pauses.
- Audio with clipping or loudspeaker feedback.
- Long recordings that may challenge memory or processing time.

Verify that:
- The uploaded file is processed by the real model.
- The cleaned file can be played and downloaded.
- Output loudness is measured correctly.
- Normalization does not introduce clipping or excessive noise.
- Failures produce helpful error messages.
- Temporary files are removed according to the retention policy.

Work in small, verifiable stages:

1. Inspect the environment and confirm the deployment target.
2. Build the upload interface and backend.
3. Implement and test real noise reduction.
4. Add loudness normalization and peak control.
5. Add progress reporting, playback, and downloads.
6. Test error handling and longer recordings.
7. Deploy the working application and verify it using a real audio file.

Create all required project files and explain their purpose in beginner-friendly language.

At the end, provide:
- The public application URL.
- The deployment status.
- The audio-processing pipeline actually implemented.
- The supported input and output formats.
- The tested maximum file size and duration.
- Any remaining limitations.
- Any external services or paid resources required.

**Important:** A successful build means that the deployed application genuinely cleans audio, not merely that the webpage loads. Never claim a feature, integration, test, or deployment succeeded unless it has actually been verified.
